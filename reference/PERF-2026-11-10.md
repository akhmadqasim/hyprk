# hyprk performance: measured costs and proposals (2026-11-10)

Nothing in the repo was edited for this report. All numbers come from a private headless session
(Hyprland 0.57.2 nested, `MBA` output 2560x1664 @ 2x, 60 Hz, plus the nested window output 2560x1440 @ 1x),
liquidglass + hyprkmotion plugins loaded, on this PC (AMD RX 6600, Mesa 26.0.8).
Shell snapshot = HEAD `fc6fda7` (working-tree edits to fonts only). File:line references are to the working tree at commit time; other agents were editing `shell/` and `ui/`, so lines may have moved. Variants were made in a scratch copy, never in the repo.

## Method and honest limits

- CPU: `/proc/<pid>/task/*/stat` (utime+stime) deltas, wakeups from `voluntary_ctxt_switches`. Hyprland is the parent
  `Hyprland` pid (the child pid is a tiny stub). `pidstat` exists, `perf` is blocked (`perf_event_paranoid=4`).
- Memory: `/proc/<pid>/smaps` (RSS, Anonymous). **PSS is unreliable here**: other agents run quickshell sessions that map
  the same files, so file PSS is divided down (SF-Pro.ttf: 48 MB RSS, 2 MB PSS). Anonymous (private) memory is the number to trust.
- Quickshell frames: `QSG_RENDER_TIMING=1` log, timestamped; counts frames per window, polish time, render time, gaps.
  `swap=16 ms` in that log is the vsync wait, not CPU. Render submission was 0 ms in nearly all frames.
- Compositor GPU: the plugin's own timestamp queries (`plugin:liquidglass:stats = 1`, `hyprctl liquidglass`). The per-glass-element
  number is usable (stable to 0.01 ms). The "whole frame" number is **not**: avg 7.4-8.5 ms, p95 ~16.5 ms (= one vsync), and it did not
  move when I turned off glass, titlebar, window shadow, rounding, blur, or blur passes. The GPU is shared with the host desktop and
  other sessions (`gpu_busy_percent` read 9-26 % while my session was idle). The first sample after a long idle is also an outlier
  (max 27 s), so I quote counts and per-element times only.
- Dropped frames: the output is 60 Hz only (the headless output offers no other mode), so **120 Hz was not measured**.
  A frame gap above 20 ms in the qs log is counted as a drop. Pointer paths were scripted with `scripts/vptr`.
- Two mistakes of mine to disclose: twice (about 2.5 min in total) I started a qs from my harness with the host Wayland socket
  instead of the nested one (layer-shell was missing, so its windows were ordinary toplevels). It happened in the user's
  GNOME session. I killed both PIDs; the harness now asserts the nested socket. Numbers from those two runs were discarded.
- Not measured: 120 Hz, a real 4K 1.5x output (the plugin README has the 3840x2160 element cost), battery/power, VRAM of the
  layer-shell buffers, Hyprland's own blur/shadow cost (the whole-frame timer cannot resolve it), fresh-boot cold caches.

## 3. Glass plugin (RX 6600, `full_damage = 1` plus a foot window redrawing at 200 Hz so every frame draws all glass)

| Test | glass GPU per element (avg) |
|---|---|
| Dock only (1 element) | 0.43-0.52 ms (stable runs 0.435) |
| Dock + menu (2 elements) | 0.47 ms each |
| Dock + Control Center (2) | 0.56 ms each |
| Dock + Notification Center (2) | 0.45 ms each |
| Launchpad open (full-screen glass) | 1.32-1.66 ms |
| Output 1920x1080 / 2560x1664 / 3840x2160 | 0.333 / 0.423 / 0.608 ms |

Which pass dominates: toggled at runtime, one at a time, dock only, 5 s each (baseline 0.435 ms):
`shadow_scale 0` 0.435, `ring_scale 0` 0.435, `aberration 0` (7 taps to 1) 0.417, `refraction_scale 0` 0.411,
`blur_lod_scale 0` 0.432, `highlight/rim/inner_shadow 0` 0.432, `pointer_light 0` 0.429, `appearance 'light'` (no luma readback) 0.429,
Hyprland `decoration.blur` passes 1 / 2 / 3 / 4 / off: 0.59 / 0.45 / 0.52 / 0.85 / 0.434 (the 1 and 4 runs were polluted by other GPU users;
blur off equals baseline, so passes do not matter for the element). **The shader terms are worth 0 to 0.03 ms.** The cost is a fixed
overhead that scales weakly with output size (0.33 ms at 1080p, 0.61 ms at 4K): per element the plugin blits the backdrop at full
resolution and calls `glGenerateMipmap` on **two whole-output-sized textures** (`plugin/src/GlassElement.cpp:321` blit, `:330` mips of the sharp copy,
`:529` blur, `:546` mips of the blurred texture, then the draw), however small the glass is.

Backdrop scale (LIVE-27.2.1: Apple renders the backdrop at 0.5 for D < 160 pt and 0.25 above): **the plugin does not downsample.**
`blurMainFramebuffer(ctx, 1.f, ...)` takes a blur strength, not a scale; the sharp copy is 1:1; the mip chain is the only downsampling.
Total glass cost is under 1.2 ms per frame at 2560x1664 with two layers, so this is a small cost today, and a 0.5/0.25 backdrop would
change the look (not proposed).

Hyprland itself at 60 fps (foot at 200 Hz redraw): 6.5-8 % of one core = 1.1-1.4 ms per frame, the same with plugin on/off, titlebar on/off,
window shadow on/off, blur on/off. So the plugin's CPU cost per frame is below what I can resolve.

## 4. Startup

| Step | Time |
|---|---|
| Hyprland process start to socket lock | 0.36-0.40 s |
| IPC ready (`hyprctl version` answers) | 0.50 s |
| `qs` launched (by `hyprland.start`) to first window GL context | **2.24 s** (all 6 windows 2.31 s) |
| Hyprland start to Dock + menu bar + wallpaper layers mapped (both outputs) | **2.5 s** (poll 30 ms) |
| qs CPU during those 2.3 s | **2.9 CPU-s, one core at 100 %** (`/proc` 290 ticks) |
| qs anonymous memory | 5 MB at launch, **442 MB at +5 s**, 328 MB at +15 s, 342 MB at +38 s (0.11 s GC burst), 281 MB at +81 s (0.16 s GC burst), about 220 MB after 4-5 min |
| tail | two GC bursts (0.1-0.16 s of CPU each) at about 38 s and 81 s |

The 2.24 s before the first window is pure QML object instantiation (one thread): the QML disk cache makes no difference
(`QML_DISABLE_DISK_CACHE=1`: 2.23 s vs 2.26 s). I attributed it by removing pieces in a scratch copy (section 5):
**AppIconTile alone is 1.3 CPU-s and 188 MB of that.** `wallpaper.sh` (the blurred copy and the luma) costs 1.76 s cold in a separate
process (277 MB peak, 46 MB 6016x6016 PNG source) and 0.03 s warm; it is respawned on every `width`, `height`, `dark` and `chosen`
change (`shell/services/Wallpaper.qml:28-38`, up to 3 times at startup, all warm after the first run).

Other memory items:
- Wallpaper: `Image` is decoded at logical size (`Background.qml`, `cache: false`); the cached wall is 1280x832 (915 KB), blurred copy 275 KB. Not a cost. The 6016 px sources are only read by `magick`.
- Notification Center photo: `sourceSize.width = 640` (`NotificationCenter.qml:428`), about 1 MB decoded, kept by design. Not a cost.
- Launchpad preload (`5f6a680`): the comment says "about 1.5 MB at 2x for 35 icons"; measured it is **144 MB peak, 87 MB settled and 1.1 CPU-s** because every `AppIcon` is an `AppIconTile` (cost 1). `Apps.sortedEntries` alone costs +19 MB and 0.09 s.
- Fonts: `SF-Pro.ttf` (7.8 MB) is mapped 10 times (48 MB RSS, one copy in the page cache), `SF-Mono-Italic.ttf` once, one Ubuntu Sans fallback 3 times. `AppleColorEmoji.ttf` is 82 MB in the working tree (new today); it is not mapped yet because nothing draws emoji. Re-measure when it is used.
- Icon caches: `IconShape.cache` is a few KB. Qt pixmap cache holds only the scaled icons. The shell icon PNGs are 128 and 512 px.
- Finder and Settings: see section 6.

## Top 10 costs, ranked by impact

Savings marked "measured" come from a scratch copy that I ran; the others are estimates.

**1. `AppIconTile` builds its whole squircle tile for every icon, even when it is never shown.**
`ui/HyprK/AppIconTile.qml:62-65` (`_unit`, `_inset()`: about 100 `Qt.point` per call, 4-5 calls per icon),
`:68-143` (`Item { id: tile; visible: root.tiled ... Shape { 6 ShapePath, 3 gradients } }`). `tiled` is false for every trusted macOS icon, which is nearly every icon here.
Used by Dock (`shell/modules/Dock.qml:271`, once per screen), Launchpad preload (35), Spotlight rows, Switcher, Apps window, Finder `finder/qml/FileIcon.qml:92`, Settings `settings/controls/PaneIcon.qml:20`.
Fix: put the tile in `Loader { active: root.tiled; anchors.fill: parent; sourceComponent: ... }` and compute `squirclePoints(100)` once in `iconshape.js` (a `.pragma library` variable), not per instance.
Measured (Loader only): shell start to Dock mapped **2.35 s to 1.12 s**, startup CPU **2.9 to 1.7 CPU-s**, anon at +6 s **448 to 260 MB**, anon at +60 s **325 to 229 MB**, RSS 513 to 416 MB.
Identical: pixel diff of `grim` screenshots, Dock crop and Launchpad open, baseline vs variant: **0 of 4,096,000 differing pixels for the Dock, 6 for Launchpad** (noise). Not yet checked: a non-trusted icon (e.g. `QS_ICON_THEME=WhiteSur`), where the tile is drawn and the Loader's anchoring must reproduce the same position; diff that case too before merging.

**2. Mission Control captures every window at 60 fps while open.**
`shell/modules/MissionControl.qml:189` `live: mc.shown`. Three idle foot windows: Hyprland 5.5 %, qs 5.2 %, 600 compositor frames in 10 s, 2100 wakeups/s. It scales with the window count and keeps the GPU out of idle.
Fix: `live: false` plus one capture when the cell appears (or a `Timer` at 2-4 Hz that calls `captureFrame()` for windows that changed). Expected: idle Mission Control drops to about 0 % and 0 frames/s (the open/close animation is unchanged).
Identical: screenshot of Mission Control 0.5 s after opening with static windows, before and after, pixel diff 0 (only a window that is itself animating differs, which macOS also updates live: say so before choosing 0 Hz).

**3. A second output costs 80 MB and 0.7 CPU-s at startup, and Overlay + ControlCenterWindow exist on every output.**
`shell/shell.qml:15-26` creates Background, MenuBar, Dock, Overlay and ControlCenterWindow per screen. Measured: one output only: -78 MB, -0.73 CPU-s; no Overlay and no ControlCenterWindow (both outputs): -21 MB settled, -33 MB peak, -0.45 CPU-s.
Fix: create `Overlay` and `ControlCenterWindow` through a per-screen `LazyLoader` that activates the first time that screen is `Panels.activeScreen` (menus and Control Center only appear on the active screen). Expected: 20-30 MB and 0.2-0.45 s on a two-output setup, nothing on one output.
Identical: open menu, Control Center, Notification Center on both outputs, pixel diff of both screenshots.

**4. The Launchpad preload sits on the startup critical path.**
`shell/modules/LaunchpadPreload.qml:22` (35 `AppIcon`), instantiated from `shell/modules/Background.qml:29`. After cost 1 it is much cheaper, but it still runs inside the 1.1-2.3 s before the first window. With plain `Image` delegates it still costs +33 MB / +0.3 s vs none.
Fix: start it from a `Timer { interval: 2000 }` (or `Qt.callLater` after the Dock is up) so the Dock and menu bar appear first; keep the icon `Image`s at `sourceSize` (they are cached by url and size, so Launchpad finds them). Expected: 0.3 s and about 30-60 MB off the time to first paint; first Launchpad open unchanged because the preload still finishes long before a user can press the key.
Identical: first-frame screenshot of Launchpad 100 ms after opening, 2 s after login, pixel diff 0.

**5. Glass element fixed cost: two whole-output mip chains and a full-resolution blit per element per frame.**
`plugin/src/GlassElement.cpp:321` (full-resolution blit), `:330` (`glGenerateMipmap` on the sharp copy), `:529` (blur), `:540` (copy), `:546` (mip on the blurred texture), per element. 0.33 ms at 1080p, 0.43 ms at 2560x1664, 0.61 ms at 4K, 1.3-1.7 ms for a full-screen element (Launchpad); shader terms are only 0 to 0.03 ms. Two layers (Dock + menu) cost about 1 ms per redrawn frame, 6 % of a 60 Hz budget on this GPU; it is probably larger on a weaker GPU.
Fix: copy only the box (plus the 128 px footprint) into a box-sized texture and mip that, or limit `GL_TEXTURE_MAX_LEVEL` to the level the recipe reads (`blur_lod_scale` 0 lowered the cost by 0.003 ms only, so the mip size, not the level count, is the cost). Expected: 40-60 % of the element cost, 0.2-0.3 ms per element per frame. Do not add a 0.5/0.25 backdrop scale: it changes the look.
Identical: `full_damage = 1` screenshots of Dock, menu, Control Center, Launchpad before and after, diff must be 0 (README records a 0 diff test for `full_damage`).

**6. Spotlight keystrokes cost about 60 ms of qs main thread each.**
6 queries cost 0.37 CPU-s beyond open/close; 24 of 276 frame gaps exceed 20 ms. Ruled out by test: `AppIconTile` (same numbers after cost 1), file search (`Binding` to `FileSearch.query` forced to "": 56 vs 60 ticks). Suspects (not proven): each query changes `rows` (`shell/modules/Spotlight.qml:70-98`), which rebuilds all result delegates, then the glass grows on a spring and `ShellWindow.settleGlass` re-measures all glass regions and rebuilds `glassUnion` every frame (`shell/components/ShellWindow.qml:61-70`, `:96-100`).
Fix: needs a profiler run (QML profiler on the scratch copy) before changing code; keep rows keyed by identity so unchanged rows are not recreated. Expected: 2-3x less main-thread time per keystroke. Not measured further because `perf` is blocked.

**7. Startup memory transient: 440 MB anon at +5 s, 220 MB at rest.**
Follows from cost 1 and the object count; the GC gives it back in two bursts (0.11 s at +38 s, 0.16 s at +81 s). Fixing cost 1 lowers the peak to 260 MB. If a lower peak matters after that, call `gc()` once from a `Timer` 3 s after startup so the reclaim happens in one place instead of two later bursts. Expected: no 38 s / 81 s CPU blips.
Identical: nothing visual changes.

**8. Launchpad glass is full-screen: 1.3-1.7 ms per redrawn frame, and the cursor blink redraws it.**
Measured 14 frames per 8 s while open and idle, each with glass at 1.7 ms. Fix: nothing to do beyond cost 5; optionally stop the search field's blinking cursor while the pointer is idle (no look change on a screenshot). Expected: negligible, listed so it is not rediscovered.

**9. Wallpaper pipeline spawns `wallpaper.sh` up to 3 times at start and decodes the Image twice (one per output).**
`shell/services/Wallpaper.qml:28-38` (`onWidthChanged`, `onHeightChanged`, `Component.onCompleted`, `onChosenChanged` each call `refresh()`), `shell/scripts/wallpaper.sh` (luma `magick` runs even when cached). Cold run: 1.76 s, 277 MB peak, one time per size/dark/wallpaper change; warm run 0.03 s. Image decode: 25 MB for two outputs (`Background.qml`, logical size).
Fix: debounce `refresh()` with a 0-interval `Timer` (one spawn per change burst); skip the luma `magick` when the cached wall is unchanged (store LUMA in a sidecar file). Expected: saves about 60 ms and two process spawns at each start; zero visual change. Keep the logical-size decode: raising it changes the look.

**10. Small steady items.**
- Trash retry timer on a fresh account (`shell/modules/Dock.qml:119-124`): a permanent 5 s wake plus a `FolderListModel` reload per Dock. Fix: retry every 60 s instead of 5 s, or create the Trash folder's parent watch once. Expected: removes the 4 wakeups/s on a clean account.
- One window repaints with 11 ms polish every 50-65 s and does not draw (unidentified binding): `qt.scenegraph.time.renderloop` shows `polish=11 ms, render=0 ms`. Cost 0.2 ms/s. Find it with `QSG_RENDER_TIMING` + `QML_IMPORT_TRACE` only if idle power matters.
- `AppleColorEmoji.ttf` (82 MB) once emoji are drawn: measure then, it is file-backed so only touched pages count.

## Reproducing

All of it ran from scratch scripts (not committed): start `config/hypr/start.sh` with `HYPRK_ROOT` set to a scratch snapshot, create `MBA`,
drive panels with `qs -p <shell> ipc call panels ...`, the pointer with `scripts/vptr`, windows with `hyprctl dispatch 'hl.dsp.window.*'`,
and read `hyprctl liquidglass` plus `/proc`. The plugin config keys used at runtime: `plugin:liquidglass:stats`, `full_damage`, `shadow_scale`,
`ring_scale`, `aberration`, `refraction_scale`, `blur_lod_scale`, `highlight`, `rim`, `inner_shadow`, `pointer_light`, `appearance`, and
`decoration.blur.passes/enabled`. A real baseline and variant comparison for any fix above is: same snapshot, restart only qs
(`qs -p <dir>` with the Hyprland environment plus `HYPRK_GLASS=plugin`, `QT_QPA_PLATFORM=wayland`, `QSG_DISTANCEFIELD_ANTIALIASING=gray`),
sample `/proc/<qs>/stat` and `smaps` at +6 s, +30 s, +60 s, and diff `grim -o MBA` crops with `magick compare -metric AE`.
