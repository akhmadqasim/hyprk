macOS 27.2.1 (26B131) vs 27.2 (26B123): what changed
Compared 2026-11-10 on the PC from the two IPSWs (dyld cache + OS volume + AppOS volume).
No Apple files are in this repo. Local copies: ~/Downloads/macos/dyld-27.2.1 and work-27.2.1.

Source
- UniversalMac_27.2.1_26B131_Restore.ipsw, 25595954706 bytes, from updates.cdn-apple.com
  (same URL as the ipsw.me redirect for Mac14,15 26B131).
- SHA256 233e85a0...f300814f, SHA1 834e8fd6...fc1462df, MD5 694c21aa...5e37 all match ipsw.me.
- Volume SystemVersion.plist: ProductVersion 27.2.1, ProductBuildVersion 26B131.
- Volumes: OS 141-12228-174, AppOS 141-12233-179, SystemOS 141-12293-176 (27.2 had -170, -175, -172).

Summary
It is a maintenance update. By file hash and dyld image UUID, nothing in the volume/brightness
HUD or the Liquid Glass stack changed.

Volume and brightness HUD
- Owner: /System/Library/CoreServices/OSDUIHelper.app (OSDMeterView, OSDMeterViewLight/Dark,
  OSDRoundWindow, OSDWindowController, Swift BSUIMeterBlocks), plus OSD.framework (in the cache).
- OSDUIHelper.app (29 files, binary and resources) is byte-identical. OSD.framework, BezelServices,
  DisplayServices and CoreBrightness are identical in the cache (same UUID, same text size).
- So a different look of the volume or brightness UI is NOT explained by any HUD binary or asset.
  Only shared AppKit and CoreUI were rebuilt (see below), and their strings and assets are unchanged.

Identical (no change at all)
DesignLibrary, QuartzCore, CoreMaterial, CoreMaterial3D, SkyLight, SwiftUI, FrontBoard,
WindowManager.framework, ControlCenter.framework, HIServices, CoreSVG, CoreGlyphs.
On disk: Dock.app (392 files), WindowManager.app, NotificationCenter.app, Finder.app (3250 files),
OSDUIHelper.app, OSD.framework resources.

Rebuilt but equivalent as far as checked
- AppKit (cache image): new UUID, same text size. Strings differ only in the build temp dir name.
  Resources: Assets.car, VersionsButtons.car, 4 Touch Bar .car and 7 nibs differ by about 100 bytes
  per file at the same size, no new strings. Not decompiled, so a code change cannot be excluded.
- CoreUI: new UUID, same text size. DesignLibrary-macOS.bundle macOSRepositories/*.car differ in
  a few header bytes. LightStandard.car (8 vector glyph effect renditions) has the same fields in a
  different serialization order, no value changes found.
- IconServices, IconFoundation, CoreUtils family: new UUID, no string changes.
- ControlCenter.app: binary identical. Only 3 .loctable files differ at the same size
  (KeyboardBrightness, ScreenMirroringAlert, ControlCenterHelper BackgroundReplacement).
  SystemUIServer.app: only AskDialogContents.loctable.

What really changed (176 of 4115 cache images by UUID, 2451 of 312947 volume files)
- Bluetooth: IOBluetooth(UI), CoreBluetooth(UI), BluetoothManager, BluetoothAudio, bluetoothd, BTCSEngine.
- AirPlay: AirPlayReceiver/Sender(+Kit), AirPlaySupport, APTransport, MediaControl*.
- Messages/IDS: IMCore, IMDaemonCore, IDS, IDSFoundation, MessagesKit, ChatKit, Messages.app, imservice plugins.
- Spotlight (about 25 frameworks, size changes) and CoreSpotlight.
- ScreenTime (about 15 frameworks, Screen Time.app, settings extension).
- SMB (SMBClient, smbfs.kext), kernel extensions, kernelmanagerd, MobileAsset(+Daemon), Nexus.
- Crypto and TLS: libcrypto and libtls dylibs in the cache (size +300 bytes each), /usr/bin/openssl,
  ocspcheck, plus ssl cert.pem.
- loginwindow (binary + helpers), Clock.app (binary + widget), Rapport(UI), HybridDatabase (-155 KB),
  JetEngine, libcompression, compression_tool, mdfind/mdimport/mdutil, uarp*.
- Not compared: the SystemOS volume apart from its dyld cache.

App icons (72 apps in themes/icons/apps-sources.txt)
- 69 have a byte-identical Assets.car.
- Clock, Messages and Bluetooth File Exchange have a different Assets.car (same size), but every
  AppIcon rendition payload is identical. Only build GUIDs in rendition names and metadata differ.
- So no app icon changed. 27.2 icons remain valid.

Method notes
- Cache images compared by UUID and text size from dyld_cache_image_text_info, then by strings;
  disk files by SHA256 over all of /System, /Library, /Applications, /usr, /Users of both OS volumes.
- ipsw dyld extract fails on this cache (failed to remap symbol _objc_msgSend$...), so dylibs were not
  extracted with ipsw. Use the repo's tools/dsc.c route on the Mac.
