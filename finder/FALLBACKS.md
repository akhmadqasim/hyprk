# Finder fallbacks

What the Finder does when a macOS-like resource is missing.

| Missing | Fallback | Where |
|---|---|---|
| Thumbnail | `image://thumb` (worker threads, never the UI thread): freedesktop cache `~/.cache/thumbnails/{x-large,large,normal}`, then our cache `~/.cache/hyprk-finder/thumbnails/<md5 uri>-<mtime>.png`, then generation at 512 px: images via QImageReader, PDFs via `pdftoppm` (first page). Videos only show a thumbnail when GNOME already cached one. Empty files and anything else get the file-type icon. | `src/thumbnails.cpp`, `qml/FileIcon.qml` |
| Document icons | 27.2.1's composed pages (reference/re/27.2.1/ICONS-REA-27.2.1.md part 2): `icons/doc-<kind>@<pt>pt.png` for docx, xlsx / csv, pptx, html, audio, video, images without a thumbnail and other text (built by themes/icons/tools/build-docs.py, no text) with the extension drawn at run time (`lib/files.js docText`); the Mac's renders for txt / zip / pdf. A file whose kind has no art (no extension or MIME match): the generic page below. | `qml/FileIcon.qml`, `qml/lib/files.js` (`macDocKind`) |
| File-type icons | macOS PNGs from `themes/icons/system` (GenericDocumentIcon with an extension badge, GenericFolderIcon, Documents/Downloads/Desktop/... folder icons, GenericApplicationIcon). If that folder is missing, original drawn SVG folder/document icons. | `qml/Theme.qml` (`sysIcon`, `folderIcons`), `qml/lib/icons.js` |
| App icon (Applications) | `QIcon::fromTheme` in the current theme, then Adwaita, then hicolor. XDG `icons` dirs are added to the search path because Qt only searches `:/icons` without a platform theme. If nothing is found, the generic document icon. | `src/main.cpp` (`IconProvider`) |
| SF Pro | `themes/fonts/SFNS.ttf` is registered at start (family "System Font"). If it is absent: Inter, then Cantarell, then the default sans. SF is a variable font whose default optical size is display (opsz 28), so text pins `opsz 17` and sets `wght` through `font.variableAxes`; other fonts ignore the axes. | `qml/Theme.qml` (`pickFont`), `src/main.cpp` (`loadFonts`) |
| Blur behind the window | Solid sidebar: the 27.2.1 Finder's measured fill, light (237,237,238), inactive (242,242,243), dark (36,38,55) (MAC-ANSWERS.md Q-finder-03; the dark value carries the tint of the Electric Blue wallpaper it was measured over). Set `HYPRK_BLUR=1` only when the compositor blurs behind the window (Hyprland windowrule for class `hyprk-finder`), then the sidebar uses the 27.2.1 sidebar glass fill (light 0.87/0.88/0.91 at 70%, dark 0.15 at 75%). | `qml/Theme.qml` (`sidebarSolid`, `sidebarGlass`) |
| Scroll pocket under the toolbar (icon view) | HyprK `ScrollEdge` (shader, the decoded ThinFilm pocket). Reduce Transparency: the band is the plain window colour. Without shader support the band is not drawn and the icons pass under the toolbar unblurred. | `qml/Main.qml` (`keys.underToolbar`), `ui/HyprK/ScrollEdge.qml` |
| Window shadow | None drawn by the app (an in-window shadow would need a margin and break tiling). The compositor draws it. | `qml/Main.qml` |
| Rounded corners | The frame, sidebar and content corners are drawn with a 22 px radius on a transparent window. If the compositor does not support alpha, the corners show its background. Maximized windows drop the radius and border. | `qml/Main.qml` |
| SF Symbols | The real outlines from `themes/icons/sf-symbols` (`qml/lib/sf.js`, a symlink to the generated `sf.js`) are tinted SVG data URLs, so they also work with the software backend. Names without an SVG (`zoom`) use the original 24x24 glyphs. | `qml/lib/symbols.js` |
| Trash | `gio trash`, run asynchronously so the UI never blocks. When it fails (for example tmpfs or a mount without trash support) the item stays and an alert shows the reason. | `FileOps::trash` |
| Share sheet | No Linux equivalent: Share opens the selection. | `qml/Toolbar.qml` |
| Tags | Stored in the xattr `user.xdg.tags`; on filesystems without user xattrs they live in `~/.local/share/hyprk-finder/tags.json`. That JSON also indexes every path tagged from the Finder, which is what the sidebar tag lists show (files tagged by other tools are not indexed). Tag from the toolbar Tag button or the context menu dots (click toggles). | `src/fileops.cpp` (`tags`, `setTags`) |
| Shared, iCloud Drive, AirDrop | Sidebar placeholders that do nothing; iCloud Drive and AirDrop are dimmed. | `qml/Sidebar.qml` |
| Sort By / Clean Up By | The Mac's rows (ArrangeByMenu.nib, Clean Up By table); orders with no data here (None, Snap to Grid, Date Last Opened, Date Added, Date Created, Tags) and every Clean Up By row are disabled. The toolbar's Action button shows the context menu, as on the Mac. | `qml/Main.qml` |
| Group By (toolbar group button) | The nib's Group By rows; there is no grouping here, so None is checked and every other row is disabled. The ⌥-click Sort By alternate is not built. | `qml/Main.qml` (`groupItems`) |
| Preview pane Show More (gallery, column preview) | The link shows as on the Mac (PV1) but does nothing: the extra metadata rows it opens on the Mac were not captured and there is no importer for them here. No made-up rows. The gallery shows it for images and PDFs only (R9.2: none for a folder or a text file; other kinds were not captured). | `qml/InfoRows.qml`, `qml/GalleryView.qml` |
| Gallery inspector rows (R9.2) | Dimensions comes from the image header (`FileOps.imageSize`, QImageReader, EXIF rotation applied); an image Qt cannot read has no Dimensions row. "Last opened" shows, as on the Mac, only for a file with a last-used date (R9.2: none for files never opened, so Created / Modified / Dimensions and Tags at 248 pt). macOS's date (set by LaunchServices when an app opens the file) has no counterpart here; the file's `recently-used.xbel` record (the later of its modified / visited) stands in, so a file opened by an app that does not write that list has no row. Access time is not used (a thumbnailer or a copy moves it). | `src/fileops.cpp`, `qml/InfoRows.qml` |
| Gallery preview (R9.1-R9.3) | Image: the file itself, decoded at the frame's size off the UI thread; the old picture stays until the new one is ready (`retainWhileLoading`), so a key press cuts over with no blank frame. PDF: the first page via `pdftoppm` (image://pdfpage, the cached thumbnail until it is rendered); without `pdfinfo` the icon. Text: the first 64 KB in `Theme.fontMono` at 11 / 13 pt (Menlo is not installed). Anything else, folders included: the file icon at 0.944 of the frame height, at most 512 pt (fitted to two Mac stills, the Mac's rule is not known). | `qml/GalleryView.qml` |
| Gallery inspector material (R11.1, R11.3) | The Mac's layer tree cannot be read (SIP), so the column is a fit on the stills, not the Mac's filter list: the plain colour (236,237,238 / 36,37,53) plus two blurred copies of the gallery content behind and beside it, sigma 10 pt (R11.3: 10-12) and 80 pt, each with a luminance and a colour gain (`Theme.gallery.pane*`). Against `gallery-715x715-*`: rms 0.9 / 1.1 of 255 over the column, 2.5 / 3.1 (max 8 / 12) on R11.1's table; the rest is the Mac's response not being linear (the dark blue and green are off most). Thumbs beyond the window's right edge are not drawn, so not in the blur. With compositor blur (`HYPRK_BLUR=1`) the same glow goes over the sidebar glass fill; not compared. The sidebar does not show the strip or the preview through it yet (R11.1 last point). | `qml/GalleryView.qml`, `qml/shaders/inspector.frag`, `qml/shaders/gauss.frag` |
| Gallery wheel (R11.2) | Measured with line events only: a horizontal or Shift notch is 10 pt in one frame, a vertical notch does nothing. A real wheel's acceleration and a trackpad over the strip were not captured: a trackpad scrolls the strip as any Flickable here. A vertical notch over a text preview scrolls its text (not captured on the Mac). | `qml/GalleryView.qml` |
| Gallery Hide Preview (R9.4) | View > Hide Preview ⇧⌘P (Ctrl+Shift+P; the shell's View menu sends it) hides the inspector for this session; Finder stores it in `StandardViewOptions.GalleryViewOptions.ShowPreviewPane`, here nothing is stored (as the path bar). The menu row does not flip to "Show Preview": the shell menu has no state from the app. `--hide-preview` starts with it hidden. | `qml/Main.qml`, `shell/lib/menus.js` |
| Sidebar context menu | The Mac's sidebar rows (files.js `sidebarMenu`). Open in New Tab, Show in Enclosing Folder and Get Info act; Remove from Sidebar, Add to Dock, Share, Eject, Rename and Delete Tag show disabled (the sidebar is a fixed list, no Dock pinning, share sheet, eject backend or tag store edits from here). | `qml/Sidebar.qml`, `qml/Main.qml` (`sidebarMenu`) |
| Text field menu | HyprK `TextMenu` (rename field, Rename sheet, tag field, toolbar search field): Cut, Copy, Paste, Paste and Match Style (a plain paste), Search With Google (the browser) and the case transformations act; Look Up, Translate, Share, Spelling, Substitutions and Speech have no backend and show disabled. Glass: with the liquidglass plugin (`Tokens.popupGlass`, popup_classes ^hyprk-finder) the plugin's menu glass behind it and no fill; without the plugin, or with Reduce Transparency / Increase Contrast, the opaque menu fill, stroke and a 0.2 s fade. | `ui/HyprK/TextMenu.qml`, `ui/HyprK/textmenu.js` |
| The window's pixel ratio for lines at a fractional scale (1.6) | Separators and hairlines (sidebar edge, list header lines and column separators, column dividers, the toolbar divider, menu separators, gallery and Get Info hairlines) are whole device pixels, `Pixel.line(pt, Pixel.ratio(Tokens.dpr, Screen.devicePixelRatio))` with `Tokens.dpr` = `windowInfo.dpr`: 1 pt = 2 px at 1.6 everywhere, 0.5 pt = 1 px, never 0. Before the first frame (ratio 0): the screen's ratio (2 at 1.6). `reference/re/27.2.1/SCALING-AUDIT.md` | `ui/HyprK/pixel.js`, `qml/Main.qml` |
| Reduce Motion (view switcher press) | The capsule does not lift while the switcher is held (27.2.1 lifts it 2.1 pt in about 50 ms, R6.3); the hovered / pressed colours and the one-frame jump of the pressed pill stay. | `qml/Toolbar.qml` (`viewsLift`) |
