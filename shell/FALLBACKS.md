# hyprk shell fallbacks

Every surface has a designed state for missing features, so nothing looks broken
(no empty boxes, no error text). Logic that decides availability lives in
`lib/state.js` and is unit tested (`node shell/tests/run.mjs`).

| Missing | Detection | What the user sees |
|---|---|---|
| Glass blur (no ImageMagick, blurred wallpaper not produced) | `scripts/wallpaper.sh` prints empty `BLUR=`, `Theme.blurAvailable = false` | Solid tinted material, like macOS "Reduce transparency": `Theme.glass.solid` (#ECECEE light, #2A2A2C dark). Same radii, rim and shadow. |
| User wants no transparency | `Theme.reduceTransparency`, from `state/appearance.json` `{"reduceTransparency": true}`, the Control Center display button, or `qs ipc call theme toggleTransparency` | Same solid material as above. |
| liquidglass plugin (on by default, `HYPRK_LIQUIDGLASS=0` disables) | config loads `plugin/build/libliquidglass.so` in a `pcall`; only on success it exports `HYPRK_GLASS=plugin` | With the plugin: Glass items register their shapes in `ShellWindow` (ext-background-effect region) and draw no QML material; the plugin draws tint, rim, refraction and shadow. Missing or failing plugin: QML material as below. Reduce transparency always uses the solid material. |
| Menu bar title pill and top dimming | always QML, no plugin needed: only the wallpaper is ever under the bar | The pill samples the blurred wallpaper (`shaders/topdim.frag`); without it (no ImageMagick, Reduce transparency) it is the solid material. The top dimming of bright wallpapers is a static shader strip in `Background.qml`, drawn once per wallpaper. |
| Compositor glass plugin | not required | The shell draws its own frosted material from the blurred wallpaper. Hyprland layer rules (`config/hypr/hyprland.lua`) add real blur of windows behind when available. |
| Wallpaper | no image in `themes/wallpapers` | Generated blue/purple gradient (cached in `~/.cache/hyprk`). No ImageMagick: the background layer shows a flat `#3a6fb0` / `#1c1c1e`. |
| Battery (desktop PC) | `State.hasBattery(UPower.devices)`: needs a present, power-supply battery | Battery item hidden in the menu bar (macOS desktops show none). |
| NetworkManager / Wi-Fi device | `State.wifiDevice(Networking.devices)` | Menu bar Wi-Fi icon hidden. Control Center Wi-Fi module dimmed, subtitle "Not Available". |
| Wi-Fi off / not connected | device state | Menu bar shows the slashed Wi-Fi glyph at 50% opacity. CC subtitle "Off" / "Not Connected". |
| Bluetooth adapter | `Bluetooth.defaultAdapter` is null | CC Bluetooth module dimmed, "Not Available", not clickable. |
| PipeWire / no sink | `State.hasAudio(Pipewire.ready, sink)` | CC Sound module dimmed, slider not draggable. |
| Backlight (external monitor) | `brightnessctl -c backlight info` fails | CC Display module dimmed, slider shown full and not draggable. |
| Volume / brightness HUD | `services/Hud.qml`: `Audio.available`; a readable `/sys/class/backlight/*/max_brightness` | No sink: no volume HUD. No backlight: no brightness HUD (the keys do nothing either). Without the plugin the capsule is the QML material (blurred wallpaper, `Theme.glass.tintClear`, no shadow); Reduce transparency: solid. Reduce motion: fades only, no scale, at most 150 ms. Values read at startup or from a new default sink are not shown. |
| MPRIS player | `State.pickPlayer(Mpris.players)` returns null | Now Playing shows "Not Playing", empty art tile, controls at reduced opacity (macOS behavior). |
| AirDrop, Stage Manager, Screen Mirroring | no backend | AirDrop toggles a local state only; Stage Manager and Mirroring buttons dimmed. |
| Fonts | `Theme.pickFont()` checks `Qt.fontFamilies()` | SF Pro (or extracted "System Font"/.SF NS via `config/fontconfig/fonts.conf`), then Inter, Cantarell, Sans Serif. |
| App icons | `Apps.iconUrl()` | Mapped macOS icon from `themes/icons/apps`, else the icon theme, else `themes/icons/system/GenericApplicationIcon`. |
| Dock app without .desktop entry | `Search.matchEntry()` returns null | Shown with its window class as name and the generic app icon; still focusable. |
| Notification without icon | no appIcon / desktop entry | Generic app icon; title falls back to the app name, then "Notification". |
| Apps with no window after launch | launch timer (6 s) | Dock bounce stops after 6 s. |
| Power actions in a nested/test session | `HYPRK_ALLOW_POWER` unset | Sleep/Restart/Shut Down/Lock only log; Log Out exits Hyprland. |
| No running apps for Cmd+Tab | empty list | Switcher does not open. |
| Menu rows the Mac has but hyprk cannot act on (`lib/menus.js`, `services/Apps.qml`, reference/re/27.2.1/MENUS-REA-27.2.1.md) | no backing feature | Shown disabled in the Mac's place, never removed or replaced: e.g. Finder > Settings… (no Finder settings window), Sort By / Clean Up By rows, System Settings' Help rows (Apple web pages), the Dock menu's Position Left / Right (bottom only) and Minimize Using (no effect drawn). The Dock menu's Turn Hiding / Turn Magnification write `dock.json` like Settings. |
| Edit menu images and the Window menu's window list (`lib/menus.js` editIcons / windowList, `modules/MenuDropdown.qml`) | a symbol missing from `themes/icons/sf-symbols` | AutoFill (rectangle.and.pencil.and.ellipsis) and Start Dictation (microphone) are drawn without their image until the glyphs are rendered on the Mac; Emoji & Symbols has its face. The window list's ◆ for a minimised window is a small drawn diamond; the • for unsaved changes is not shown (no such state here). |
| System Settings' View menu pane list (ExtensionPicker) | no way to switch the running Settings window's pane | Not drawn (MENUS-REA gap); Back, Forward and Search stay. |
| Plus-lighter / plus-darker fills (Dock running dots, Cmd-Tab selection tile) | `Theme.compositorGlass` and not `Theme.solidMaterial` | With the plugin: fill shapes on their own surfaces (`hyprk-dock-dots(-dark)`, `fill_layers`) and a cut in the switcher's own glass region (`cut_fills`), exact against the Mac. Without it, or with Reduce transparency / Increase contrast: QML stand-ins (`shaders/plusfill.frag` dots, flat `Theme.switcher.selection` tile), exact in dark only for the dots. |
| Dock menu tail (`Glass.tail`, set by `modules/Overlay.qml` for a menu above the Dock) | `Theme.compositorGlass`, `Theme.solidMaterial`; the plugin build | With the plugin: a marker hole in the menu's glass region, the plugin draws body and tail as one glass outline (plugin/README.md "Dock menu tail"). An older plugin build ignores the hole: the plain menu. Without the plugin: the QML glass draws the same outline (`lib/dock.js menuTailPath`) under the body, the blurred wallpaper and tint through a mask, rim and hairline along the curve, no shadow of its own. Reduce transparency / Increase contrast: the solid colour in that outline. The desktop's context menu never has a tail. |
| Dock Downloads stack (fan / grid, `modules/DockStack.qml`) | `Theme.compositorGlass`, `Theme.solidMaterial`, `A11y.reduceMotion`; the Downloads folder (FolderListModel) | With the plugin: the fan's name pills and the grid's bubble are glass shapes on the hover label's namespace (`hyprk-dock-label`, Regular recipe), the grid's tail is the plugin's cartouche pointer (16 pt, the Mac's grid tail is 24). Without it: the QML glass (blurred wallpaper + `Theme.glass.tintClear`), the grid's tail a 24 pt square turned 45 deg under the body. Reduce transparency / Increase contrast: the solid `Theme.glass.solidDock`. Reduce motion: shown and hidden at once, as the Mac's animators do. No Downloads folder or an empty one: the tile shows the Downloads folder and a click opens only "Open in Finder". Pictures show their own thumbnail, other files the generic page (no per-type icons, no Quick Look). |
| Spotlight file search tool | `services/FileSearch.qml` probes plocate, locate, fd, fdfind | First found is used; else `find` over $HOME (hidden dirs skipped, 40 hits, 180 ms debounce). No recently-used.xbel: Files shows "No Recent Files". |
| Clipboard history backend | `services/Clipboard.qml`: wl-paste/wl-copy, cliphist | Off until the user turns it on (Spotlight Cmd+4 "Turn On", or `state/spotlight.json` `clipboardHistory` set to "30m", "8h" or "7d"). cliphist when installed (images show a photo glyph, no thumbnail; cliphist keeps no dates, so retention is not applied and the list refreshes when the view opens), else `scripts/clipboard.sh` in `$XDG_STATE_HOME/hyprk/clipboard` (200 items, 20 MB max each, password-manager copies skipped). No wl-clipboard: the Clipboard view says so and offers no switch. Turning it off (an explicit "off", not a missing or broken file) deletes the history. Selecting an item copies it (no auto-paste: no virtual keyboard tool assumed). |
| Spotlight actions without backend | no Wi-Fi device / Bluetooth adapter / slurp | The Wi-Fi, Bluetooth, area-screenshot actions are not listed. Power actions show "Blocked in this session" without `HYPRK_ALLOW_POWER=1`. |
| Emoji & Symbols insertion (`modules/EmojiPicker.qml`, `services/Emoji.qml`) | `scripts/emoji-insert.sh` exits 2 without wl-copy / wl-paste; no virtual-keyboard tool (wtype, ydotool) is assumed | The emoji is pasted, not typed: the script saves the clipboard when it holds text (never a copy a password manager marks secret), copies the emoji, Hyprland sends the paste key to the active window (`send_shortcut`: Ctrl+V, Ctrl+Shift+V for terminals by class, `lib/emoji.js pasteMods`), and 0.7 s later the saved text goes back. Limits: an app that does not paste on that key (a terminal not in the list, a custom paste binding, an X11 app that reads PRIMARY) gets nothing, and the emoji stays on the clipboard; an image or other non-text clipboard is lost (replaced by the emoji); clipboard history, when on, records the emoji; with the desktop focused the emoji is only copied. No wl-clipboard: picking does nothing. |
| Text field menu in Spotlight and the Emoji picker search (HyprK `TextMenu` with `host`) | `Theme.compositorGlass` | With the plugin: an in-window popup on a full-screen hyprk-overlay layer of its own (`components/TextMenuHost.qml`), so it gets the shell menus' `menu` glass (submenus on a second glass-only layer below it: one layer would merge the overlapping shapes; under the 5 pt overlap the menu's glass lies over the submenu's, the Mac's the other way). It takes the keyboard while open and closes at once (no 185 ms fade). Without the plugin: the Qt popup of the layer, drawn opaque (`Tokens.control.menuFill`, its stroke, a 0.2 s fade). |
| Emoji & Symbols position and look | a Wayland client cannot see another app's text caret | The Mac hangs the popover under the caret; here its arrow points at the mouse pointer (`hyprctl cursorpos`), above the pointer when there is no room below, centred at a quarter of the screen when hyprctl fails. It is drawn in QML (no plugin glass), so the liquidglass plugin changes nothing. Reduce Transparency: nothing of the grid shows blurred through the search field and the category bar. Reduce Motion: no growth from the arrow, it appears at full size. |
| Emoji & Symbols over an app window (host keeps the key look) | the picker layer takes the keyboard (Exclusive, for its search field), so the app under it gets `wl_keyboard.leave` and a new xdg_toplevel configure (one state fewer, not decoded): Qt reports `Window.active` false | The Mac's palette leaves the app key. Hyprland's active window does not change, so the liquidglass title bar (`Titlebar.cpp windowActive`, any non-background layer focus counts as active) stays coloured on its own. Our Qt apps keep the active look while the layer is open over them: Settings (`settings/shell.qml`, `Hyprland.rawEvent` openlayer / closelayer `hyprk-emoji` + `Hyprland.activeToplevel`) and Finder (`finder/src/hypr.cpp` `Hypr.emojiOver`, Hyprland's `.socket2.sock` + `j/activewindow`). Without Hyprland or its event socket they dim as before. Other apps (GTK, foot's cursor) still show their unfocused look: a Wayland client cannot be told it is key without the keyboard. |
| Status item modules: Wi-Fi, Battery, Focus (`modules/StatusModuleWindow.qml`, `lib/statusmodule.js`, reference/re/27.2.1/STATUS-REA-27.2.1.md) | `State.wifiDevice`, `Networking.wifiEnabled`, `UPower.displayDevice`, `Notifs.dnd`; `Theme.compositorGlass` / `Theme.solidMaterial` like Control Center | Wi-Fi without a device: the header's switch disabled, only "Wi‑Fi Settings…"; Wi-Fi off: header and "Wi‑Fi Settings…" (the Mac's lists are empty). A secured network with no saved settings is shown disabled (no password sheet here). Battery: "No Apps Using Significant Energy" shown disabled (no per-app energy on Linux); Charge to Full Now, Service Recommended and Energy Mode not drawn. Focus: Do Not Disturb only (hyprk's one mode); no lifetime drawer. Glass as Control Center's Sound module (plugin `hyprk-controlcenter` recipe; QML material without it; solid with Reduce transparency); Reduce motion: no 1 % scale. `HYPRK_STATUS_STUB=1` (tests) shows made-up networks and battery and keeps every switch and row away from the real state. |

## Settings state files (`state/*.json`, written by the Settings app)

Read by `services/Prefs.qml` (and `Theme.qml`, `scripts/sound.sh`). Missing or broken files keep the defaults
from `settings/Parsers.js`. The folder is `$HYPRK_STATE`, set once by `config/hypr/start.sh` (`state-dir.sh`): `<root>/state` if writable, else `~/.local/state/hyprk`.

| File | Effect in the shell |
|---|---|
| `appearance.json` | dark mode, Reduce transparency |
| `sound.json` | alert sound, volume, UI sounds, volume feedback (see SOUNDS.md) |
| `notifications.json` | per app (`apps["<desktop id>"]`): `allow: false` drops the notification, `style: "none"` = Notification Center only, `"alerts"` = banner stays until dismissed, `sounds: false` = silent. `previews: "never"` hides bodies. |
| `lock.json` | idle display off after `displayOffAfter` s (Hyprland DPMS); lock after `screenSaverAfter + requirePasswordAfter` s with hyprlock + `lockscreen/hyprlock.conf`, loginctl fallback, only when `HYPRK_ALLOW_POWER=1`. 0 = never. |
| `input.json` | keyboard repeat applied with `hyprctl eval` at start and on change (0.57 has no `hyprctl keyword`) |
| `spotlight.json` | `clipboardHistory` ("off" default, "30m", "8h", "7d"), `quickKeys` (`{"<action id>": "<key>"}`, written by Spotlight's "Add Quick Keys") |
| `emoji.json` | written by the shell, not Settings: Emoji & Symbols' Frequently Used (`{"used": {"<emoji>": [count, last use ms]}}`, 60 kept, 18 shown) |
| `wallpaper.json` | `path` replaces the default wallpaper; menu bar text turns dark over bright wallpaper tops |
